# The Identity Layer of the Internet

Appearance captures what a person looks like — structured, consented, and ready for any app to use.

Users complete a single face scan. Appearance analyzes multi-angle photos to produce a structured profile: face shape, hair texture, density, skin tone, and measurements. When a user connects their Appearance to your app, you receive this data immediately. No questionnaires. No photo uploads.

## What you receive

When a user authorizes your app through Sign in with Appearance, you get:

- **Scan grid** — A 2x2 composite image of the user's current appearance from their most recent reflection
- **Structured profile** — Face shape, hair type, texture, density, skin tone, and facial measurements as typed fields
- **Original photos** — Optionally, the individual scan angles (requires additional consent)

Every field is typed and constrained to known values. Your app can use them directly in logic without parsing natural language.

## How it works

1. Your app redirects the user to Appearance
2. The user sees their profile and approves what to share
3. Your app receives an access token and appearance data
4. The user's experience is personalized from the first interaction

If the user doesn't have an Appearance profile yet, they can create one during the flow. A scan takes about ten seconds.

## For AI agents

Appearance is discoverable through standard protocols. Any agent that needs to know what a user looks like can integrate without custom work.

- **MCP Server** — Query documentation and API from any MCP-compatible client
- **llms.txt** — Full documentation as a single markdown file for context ingestion
- **OpenAPI 3.1** — Machine-readable API contract for automatic tool generation
