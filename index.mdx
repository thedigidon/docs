Your users already know how they look. Appearance lets your app know too — with one tap of consent.

## What is Appearance?

Appearance builds the **identity layer for how you look on the internet**. Users do one face scan, and we capture, analyze, and structure everything about their appearance — hair texture, face shape, density, coloring, measurements — into a single, canonical profile with 50+ structured fields.

Any app that needs to understand what someone looks like can read their Appearance profile with consent. No questionnaires. No photo uploads. No cold start.

## Why This Exists

ChatGPT can ask a user what haircut they want. It can't remember what worked last time, measure their face shape, or track how their hair changes over six months. Every app that touches appearance starts from zero — questionnaires, photo uploads, guesswork.

Appearance eliminates that. Scan once, look right everywhere.

## The 5-Layer Profile Stack

Appearance captures data at five layers. Different apps need different depths.

| Layer | What It Captures | Changes | Example Consumer |
|-------|-----------------|---------|-----------------|
| **Physical Baseline** | Face shape, skin tone, hair type, texture | Years | Glasses fitting, skincare |
| **Current State** | Current haircut, length, color, facial hair | Weeks | Clothing recommendations |
| **Preference Graph** | Likes, tries, saves, skips | Every interaction | Style discovery |
| **Intent & Context** | Goals, upcoming events, growth plans | Temporal | Wedding planning |
| **Aesthetic Identity** | Overall vibe, style tribe, desired perception | Abstract | Any appearance app |

## Agent-First by Design

Appearance is built for the agentic era. Every part of our platform is machine-readable:

- **MCP Server** — Any MCP-compatible agent (Claude, Cursor, ChatGPT, VS Code) can query our docs and API directly
- **llms.txt** — Our entire documentation in a single markdown file, ready for any LLM's context window
- **OpenAPI 3.1** — Standard API contract that any agent framework can parse and call
- **Structured Responses** — Every API response uses typed, enumerated fields — no free-text parsing needed
