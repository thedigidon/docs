## Why Agents Need Appearance

AI agents are the first consumers of the Appearance API. Any agent that personalizes recommendations, helps with shopping, plans events, or gives style advice needs to know what the user looks like. Today, agents ask users to describe themselves — or skip personalization entirely.

With Appearance, an agent makes one API call and gets 50+ structured fields: hair texture, face shape, density, coloring, measurements. No questionnaires. No photo uploads. Immediate context.

## Discovery

Appearance is designed to be discovered and consumed by AI agents through standard protocols. No vendor lock-in — any agent that speaks these protocols can integrate.

## Integration Patterns

### Pattern 1: Read Appearance Data

The agent has Appearance as a tool and reads the user's profile to personalize its responses.

```
User: "I want to get a new haircut. What would work for me?"
Agent: [calls GET /v1/users/me/profile with user's token]
Agent: "Based on your profile, you have type 3B curly hair with thick density
        and an oval face shape. Here are styles that complement your texture
        and face shape..."
```

This is the simplest pattern: read the profile, use the structured fields to inform any downstream task.

### Pattern 2: Context Enrichment

The agent fetches appearance data to personalize tasks that aren't directly about appearance.

```
Agent building a travel packing list:
  → Fetches user's Appearance Profile
  → Knows user has curly hair, type 3B
  → Recommends curl-friendly travel products
  → Suggests styles that work in humid destinations

Agent planning a wedding:
  → Fetches both partners' profiles
  → Knows face shapes, coloring, hair types
  → Coordinates hair, makeup, and accessory suggestions
```

### Pattern 3: Appearance Creation

An agent helps a user build their Appearance from scratch — the onramp for users who don't have the Appearance app yet.

```
User: "I want personalized glasses recommendations but I've never used Appearance."
Agent: [calls POST /v1/scans/initiate]
Agent: "I can set that up. Open this link to do a quick 10-second face scan,
        and I'll have your measurements and profile ready."
User: [completes scan via the link]
Agent: [receives webhook when profile is ready]
Agent: [calls GET /v1/users/me/profile]
Agent: "Done! Based on your face width and bridge measurements, here are
        frames that will fit perfectly..."
```

This pattern turns every agent into a distribution channel for Appearance. The agent initiates a scan, the user completes it, and the agent immediately gets structured data to work with.

```bash
# Initiate a scan session
curl -X POST https://api.appearance.app/v1/scans/initiate \
  -H "X-Appearance-API-Key: ak_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "redirectUrl": "https://yourapp.com/scan-complete",
    "webhookUrl": "https://yourapp.com/webhooks/appearance"
  }'
```

Response:
```json
{
  "sessionId": "scan_k7Xm9pL2qR4v",
  "scanUrl": "https://appearance.app/scan?session=scan_k7Xm9pL2qR4v",
  "expiresAt": "2026-03-29T11:30:00Z"
}
```

The user opens `scanUrl`, completes their face scan, and your `webhookUrl` receives a callback with the user's access token once the profile is built.

## API Authentication

All API calls require two credentials:

| Credential | Header | Purpose |
|-----------|--------|---------|
| **API Key** | `X-Appearance-API-Key: ak_...` | Identifies your app |
| **User Token** | `Authorization: Bearer at_...` | Identifies the consenting user |

The API Key identifies your application. The Bearer token comes from the user completing the "Sign in with Appearance" OAuth flow.

## Response Format

All API responses use **structured, enumerated fields** — no free-text parsing needed. An agent can reliably extract and compare values.

```json
{
  "hair": {
    "textureFamily": 3,
    "density": "thick",
    "faceShape": "oval",
    "lengths": { "top": "short", "sides": "short" }
  },
  "structural": {
    "faceWidth": 142.3,
    "jawWidth": 126.1,
    "skinTone": { "fitzpatrick": "Type V", "undertone": "warm" }
  },
  "glasses": {
    "binocularPdMm": 63.5,
    "frameSize": "medium"
  }
}
```

Every field is typed and constrained to a known set of values. Agents can use these values directly in logic without natural language interpretation.

## Rate Limits

| Scope | Limit |
|-------|-------|
| Per API key | 60 requests/minute (free tier) |
| Per user token | 120 requests/minute |

Rate limit headers are included in every response:
- `X-RateLimit-Remaining`
- `X-RateLimit-Reset`
