## What is an Appearance Profile?

An Appearance Profile is the **complete, consolidated record** of everything Appearance knows about a user's physical appearance. One face scan — six angles, ten seconds — produces **50+ structured fields** spanning hair texture, facial geometry, skin tone, and eyewear measurements.

The profile is organized by **zone**: hair, structural (cross-zone facial measurements), and glasses. Each zone captures a different dimension of appearance. The hair zone alone contains over 40 fields across texture, color, growth patterns, condition, capabilities, and current style.

Profiles are **read-only** (auto-generated from scans) with a small set of **user-editable fields** for attributes that AI cannot detect from photos.

```json Example: accessing a profile
GET /users/me/profile
Scope: appearance:profile
```

---

## Why This Matters

These are fields no app could collect on its own in under 30 seconds.

Without Appearance, getting this data requires questionnaires ("What's your hair type?"), photo uploads ("Show us your hairline"), and professional assessment ("Your porosity is low"). Users get it wrong, skip questions, or never finish.

A face scan takes **10 seconds**. The profile eliminates questionnaires, photo uploads, and guesswork for every downstream application — styling recommendations, product matching, virtual try-on, barber briefs, and eyewear fitting all read from the same structured source of truth.

## How Profiles Are Built

<Steps>
  <Step title="User performs a scan">
    A 6-angle head capture using the device camera and ARKit face tracking. The user turns their head through front, left, right, up, down, and three-quarter angles while the app captures photos and facial landmark data.
  </Step>
  <Step title="AI analyzes the scan">
    Gemini Flash vision model receives the multi-angle photos and extracts structured hair, skin, and facial attributes. This produces texture classification, color analysis, hairline mapping, growth patterns, condition assessment, and facial hair detection.
  </Step>
  <Step title="ARKit provides measurements">
    Facial landmark geometry from ARKit delivers millimeter-precision measurements: face width, jaw width, forehead height, inter-ocular distance, cheekbone width, and more. These are physical measurements, not AI estimates.
  </Step>
  <Step title="Server consolidates">
    A Cloud Function merges AI analysis + ARKit data into a single `AppearanceProfile` document. Derived fields (capabilities like `canFade`, `canLineup`) are computed from the raw data. The profile is written to Firestore and immediately available via API.
  </Step>
</Steps>

## Hair Zone

The richest zone, with **40+ fields** across 11 categories. This is where the depth of a single scan becomes clear — texture classification, color science, growth pattern mapping, and style capability analysis, all from photos.

### Texture & Structure

The foundation of hair compatibility. Uses the Andre Walker classification system (types 1-4) with subtypes.

| Field | Type | Description |
|-------|------|-------------|
| `textureFamily` | `1 \| 2 \| 3 \| 4 \| 'bald'` | Andre Walker classification. 1 = Straight, 2 = Wavy, 3 = Curly, 4 = Coily. |
| `textureType` | `string` | Subtype within family: `'1A'`, `'2C'`, `'3B'`, `'4C'`, etc. |
| `textureLabel` | `string` | Human-readable label: `'Straight'`, `'Wavy'`, `'Curly'`, `'Coily'` |
| `density` | `'thin' \| 'medium' \| 'thick'` | How many hairs per square inch. Determines volume potential. |
| `strandThickness` | `'fine' \| 'medium' \| 'coarse' \| null` | Individual strand diameter. Fine hair lays flat; coarse holds shape. |

### Current Lengths

Lengths are bucketed, not measured in inches — buckets are what matter for style compatibility.

| Field | Type | Description |
|-------|------|-------------|
| `lengths.top` | `LengthBucket` | Top of head. One of: `bald`, `stubble`, `short`, `medium`, `long`. |
| `lengths.sides` | `LengthBucket` | Side length. Determines fade/taper feasibility. |
| `lengths.back` | `LengthBucket` | Back length. Relevant for neckline and taper styles. |
| `lengths.fringe` | `LengthBucket \| null` | Fringe/bangs length, if present. `null` if no fringe. |

### Color

Full color analysis including natural vs. treated state and gray coverage.

| Field | Type | Description |
|-------|------|-------------|
| `naturalColor` | `string` | Natural hair color (e.g., `'Dark Brown'`, `'Black'`, `'Auburn'`). |
| `naturalColorLevel` | `number \| null` | Color level on 1-10 scale. 1 = blackest black, 10 = lightest blonde. |
| `currentColor` | `string \| null` | Current color if different from natural. `null` if virgin hair. |
| `isColorTreated` | `boolean` | Whether hair has been dyed, bleached, or color-treated. |
| `undertone` | `'warm' \| 'cool' \| 'neutral' \| null` | Color undertone. Warm = gold/copper, Cool = ash/silver. |
| `grayPercentage` | `number \| null` | Estimated percentage of gray/white hair. `0`-`100`. |

### Hairline & Coverage

Critical for fade feasibility, lineup recommendations, and style matching with thinning patterns.

| Field | Type | Description |
|-------|------|-------------|
| `hairlineShape` | `string` | Hairline contour (e.g., `'straight'`, `'M-shaped'`, `'widow's peak'`). |
| `templeRecession` | `string` | Temple area recession level (e.g., `'none'`, `'slight'`, `'moderate'`). |
| `hairlineRecession` | `string` | Overall hairline recession (e.g., `'none'`, `'slight'`, `'moderate'`, `'significant'`). |
| `crownThinning` | `string` | Crown area thinning (e.g., `'none'`, `'early'`, `'moderate'`, `'advanced'`). |
| `coverage` | `string` | Overall hair coverage level (e.g., `'full'`, `'thinning'`, `'sparse'`). |
| `hasFringe` | `boolean` | Whether the user currently has bangs/fringe. |

### Growth Patterns

Where hair grows, how it falls, and where it parts naturally. Essential for predicting how a style will actually sit.

| Field | Type | Description |
|-------|------|-------------|
| `growthPattern.dominantDirection` | `string \| null` | Primary growth direction (e.g., `'forward'`, `'backward'`, `'left'`). |
| `growthPattern.cowlickLocations` | `string[] \| null` | Where cowlicks are located (e.g., `['crown']`, `['front-right', 'crown']`). |
| `growthPattern.naturalPartSide` | `string \| null` | Natural part side: `'left'`, `'right'`, `'center'`, or `null`. |
| `growthPattern.crownWhorl` | `'single' \| 'double' \| null` | Crown whorl pattern. Double whorls make certain styles harder to maintain. |

### Head & Face Context

Facial structure that influences which hairstyles are flattering. These fields exist in both the hair zone and structural zone — the hair zone copy is for convenience when doing hair-specific matching.

| Field | Type | Description |
|-------|------|-------------|
| `faceShape` | `string` | Face shape (e.g., `'oval'`, `'round'`, `'square'`, `'diamond'`, `'heart'`, `'oblong'`). |
| `headShapeProfile` | `string \| null` | Side-profile head shape (e.g., `'round'`, `'flat-back'`, `'elongated'`). |
| `earProminence` | `string \| null` | How much ears protrude (e.g., `'flat'`, `'average'`, `'prominent'`). Affects styles that expose ears. |
| `neckLength` | `string \| null` | Neck length relative to proportion (e.g., `'short'`, `'average'`, `'long'`). |

### Condition & Health

Current hair health state. Damage level and grooming are AI-detected; porosity and elasticity require user input because they can't be assessed from photos.

| Field | Type | Source | Description |
|-------|------|--------|-------------|
| `grooming` | `string` | AI | Current grooming state (e.g., `'well-groomed'`, `'growing out'`, `'unkempt'`). |
| `estimatedWeeksSinceCut` | `number \| null` | AI | How long since the last haircut. Approximate. |
| `healthIndicators` | `string \| null` | AI | Visible health signals (e.g., `'healthy sheen'`, `'dry ends'`, `'breakage visible'`). |
| `damageLevel` | `'virgin' \| 'mild' \| 'moderate' \| 'severe' \| null` | AI | Overall damage assessment. Virgin = untreated, no damage. |
| `porosity` | `'low' \| 'normal' \| 'high' \| null` | **User** | How well hair absorbs and retains moisture. Affects product recommendations. |
| `elasticity` | `'low' \| 'normal' \| 'high' \| null` | **User** | How well hair stretches and returns to shape. Indicates protein/moisture balance. |

### Current Style

What the user currently has. Used for "transition from" recommendations and cut family matching.

| Field | Type | Description |
|-------|------|-------------|
| `currentStyleDescription` | `string \| null` | Free-text description of current style (e.g., `'Short textured crop with mid fade'`). |
| `currentCutFamily` | `string \| null` | Cut family classification (e.g., `'fade'`, `'taper'`, `'scissor'`, `'buzz'`). |
| `canonicalStyleTypeId` | `string \| null` | Fixed taxonomy ID (e.g., `'textured-crop'`, `'low-fade'`, `'french-crop'`). |
| `partingStyle` | `string \| null` | Current parting (e.g., `'left'`, `'right'`, `'center'`, `'none'`). |
| `volumeDistribution` | `string \| null` | Where volume concentrates (e.g., `'top-heavy'`, `'even'`, `'flat'`). |

### Facial Hair

Full beard/mustache analysis. Relevant for styles where facial hair is part of the overall look.

| Field | Type | Description |
|-------|------|-------------|
| `facialHair.hasBeard` | `boolean` | Whether the user has any facial hair. |
| `facialHair.beardType` | `string` | Beard style (e.g., `'stubble'`, `'full beard'`, `'goatee'`, `'clean-shaven'`). |
| `facialHair.beardColor` | `string \| null` | Beard color, which may differ from head hair. |
| `facialHair.connectsToSideburns` | `boolean` | Whether beard connects to sideburns. Affects fade line decisions. |
| `facialHair.coverage` | `string \| null` | Facial hair coverage (e.g., `'full'`, `'patchy'`, `'sparse'`). |

### Capabilities (Derived)

Boolean flags computed from the raw profile data. These answer the question: "Given this user's current hair, what can they do?"

| Field | Type | Description |
|-------|------|-------------|
| `canGoShorter` | `boolean` | Has enough length to go shorter and still have a style. |
| `canGoLonger` | `boolean` | Current length supports growing out further. |
| `canFade` | `boolean` | Side/back length and texture support a fade. |
| `canLineup` | `boolean` | Hairline and texture support a clean lineup/edge-up. |
| `canLighten` | `boolean` | Current color and damage level allow lightening/bleaching safely. |

### Treatment History (User-Editable)

Chemical and heat history that AI cannot detect from photos. Users set these manually.

| Field | Type | Description |
|-------|------|-------------|
| `chemicalHistory` | `string[] \| null` | Past chemical treatments (e.g., `['relaxer', 'keratin treatment']`). |
| `colorHistory` | `string \| null` | Color treatment history (e.g., `'Bleached 6 months ago, box dyed twice'`). |
| `heatStylingFrequency` | `'never' \| 'occasional' \| 'regular' \| 'daily' \| null` | How often heat tools are used. Affects damage prediction and product recommendations. |

## Structural Zone

Cross-zone physical measurements that apply to **all** appearance zones. These come from two sources: ARKit facial landmark geometry (millimeter precision) and AI anatomical analysis (proportion ratios and qualitative assessments).

### Core Facial Measurements

| Field | Type | Source | Description |
|-------|------|--------|-------------|
| `faceShape` | `string` | AI | Face shape classification (e.g., `'oval'`, `'round'`, `'square'`). |
| `faceWidth` | `number \| null` | ARKit | Face width in millimeters. |
| `faceHeight` | `number \| null` | ARKit | Face height in millimeters. |
| `jawWidth` | `number \| null` | ARKit | Jaw width in millimeters. |
| `foreheadHeight` | `number \| null` | ARKit | Forehead height in millimeters. |
| `widthToHeightRatio` | `number \| null` | ARKit | Face width divided by face height. |
| `headShapeProfile` | `string \| null` | AI | Side-profile head shape. |
| `foreheadProportion` | `string \| null` | AI | Forehead size relative to face (e.g., `'narrow'`, `'average'`, `'broad'`). |
| `earProminence` | `string \| null` | AI | Ear protrusion level. |
| `neckLength` | `string \| null` | AI | Neck length classification. |

### Skin Tone

| Field | Type | Description |
|-------|------|-------------|
| `skinTone.fitzpatrick` | `string` | Fitzpatrick scale classification (e.g., `'Type III'`, `'Type V'`). |
| `skinTone.undertone` | `string` | Skin undertone: `'warm'`, `'cool'`, or `'neutral'`. |
| `skinTone.description` | `string` | Human-readable description (e.g., `'Medium with warm olive undertone'`). |

### ARKit Geometry (Schema v2+)

Millimeter-precision measurements from ARKit facial landmarks. Available on devices with TrueDepth camera (iPhone X and later). These are **physical measurements**, not AI estimates.

| Field | Type | Description |
|-------|------|-------------|
| `interOcularDistance` | `number \| null` | Distance between pupils in mm. Basis for PD measurement. |
| `interOcularRatio` | `number \| null` | Inter-ocular distance as ratio of face width. |
| `cheekboneWidth` | `number \| null` | Distance between cheekbone landmarks in mm. |
| `jawWidthLandmark` | `number \| null` | Jaw width from ARKit landmarks in mm (vs. AI estimate in `jawWidth`). |
| `foreheadWidth` | `number \| null` | Forehead width in mm. |
| `foreheadToChinRatio` | `number \| null` | Forehead-to-chin proportion. Key for face shape validation. |
| `chinToNoseRatio` | `number \| null` | Chin-to-nose proportion. |
| `noseLength` | `number \| null` | Nose length in mm. Used for glasses bridge fitting. |
| `nasalProjection` | `number \| null` | How far the nose projects from the face plane in mm. Critical for bridge fit. |
| `chinProjection` | `number \| null` | Chin projection from face plane in mm. |
| `jawDepthLeft` | `number \| null` | Left jaw depth in mm. Asymmetry detection. |
| `jawDepthRight` | `number \| null` | Right jaw depth in mm. Compared with left for symmetry analysis. |

### AI Anatomical Analysis

Proportion ratios and qualitative assessments from Gemini Flash vision analysis. These complement ARKit measurements with observations that require understanding facial aesthetics.

| Field | Type | Description |
|-------|------|-------------|
| `anatomical.lengthToWidthRatio` | `number \| null` | Face length-to-width ratio. Below 1.2 = wider face, above 1.5 = longer face. |
| `anatomical.thirdsBalance` | `string \| null` | Balance of facial thirds (forehead, midface, lower). E.g., `'balanced'`, `'long lower third'`. |
| `anatomical.jawlineDefinition` | `string \| null` | Jawline definition (e.g., `'strong'`, `'soft'`, `'moderate'`). |
| `anatomical.cheekboneProminence` | `string \| null` | Cheekbone prominence (e.g., `'high and prominent'`, `'flat'`, `'moderate'`). |
| `anatomical.chinShape` | `string \| null` | Chin shape (e.g., `'pointed'`, `'rounded'`, `'square'`, `'cleft'`). |
| `anatomical.symmetryScore` | `string \| null` | Overall facial symmetry (e.g., `'high'`, `'moderate'`, `'slight asymmetry'`). |
| `anatomical.symmetryNotes` | `string \| null` | Specific asymmetry observations, if any. |

## Glasses Zone

Measurement-based fitting data for eyewear recommendations. Combines ARKit-derived pupillary distance with AI face width analysis to recommend frame sizes.

| Field | Type | Description |
|-------|------|-------------|
| `binocularPdMm` | `number \| null` | Binocular pupillary distance in mm. The most important measurement for lens fitting. |
| `faceWidthMm` | `number \| null` | Total face width in mm, validated against PD-derived estimate. |
| `bridgeWidthMm` | `number \| null` | Nose bridge width in mm. Determines bridge fit comfort. |
| `frameSize` | `'small' \| 'medium' \| 'large' \| 'extra-large' \| null` | Recommended frame size category. |
| `recommendedFrameWidthMinMm` | `number \| null` | Minimum recommended frame width in mm. |
| `recommendedFrameWidthMaxMm` | `number \| null` | Maximum recommended frame width in mm. |
| `wearsPrescription` | `boolean` | Whether the user wears prescription lenses. |

## User-Editable Fields

Five fields that AI cannot detect from photos. Users set these in their profile settings. When a user updates one, the field path and timestamp are recorded in `userOverrides`.

| Field | Zone | Type | Why it's manual |
|-------|------|------|-----------------|
| `porosity` | Hair | `'low' \| 'normal' \| 'high'` | Requires a water absorption test — invisible in photos. |
| `elasticity` | Hair | `'low' \| 'normal' \| 'high'` | Requires a stretch test — invisible in photos. |
| `chemicalHistory` | Hair | `string[]` | Past treatments (relaxers, perms, keratin) aren't visible once grown out. |
| `colorHistory` | Hair | `string` | Previous color treatments may not be visible in current state. |
| `heatStylingFrequency` | Hair | `'never' \| 'occasional' \| 'regular' \| 'daily'` | Cumulative heat damage isn't always visible; frequency matters for product and treatment recommendations. |

## Profile vs. Card

The **Appearance Profile** is the full data set. The **[Appearance Card](/concepts/appearance-card)** is a compact, standardized extract designed for fast compatibility matching.

|  | Profile | Card |
|--|---------|------|
| **Fields** | 50+ | ~25 |
| **Values** | Mixed (strings, numbers, objects) | Enums only |
| **Purpose** | Deep personalization | Quick compatibility reads |
| **User-editable fields** | Yes (5 fields) | No |
| **Physical measurements** | Yes (mm-precision) | No |
| **Facial anatomy** | Yes (proportions, symmetry) | No |
| **Growth patterns** | Yes (cowlicks, whorl, part) | No |
| **Capabilities** | Yes (canFade, canLineup, etc.) | No |
| **API Scope** | `appearance:profile` | `appearance:card` |

Use the **Profile** when you need the full picture — treatment planning, barber briefs, detailed product recommendations, or any feature that benefits from knowing growth patterns, damage level, or facial proportions.

Use the **Card** when you need fast, structured matching — feed compatibility scoring, filter by texture family, or compare user-to-offering at scale.

## API Access

Profiles are accessed via `GET /users/me/profile` with the `appearance:profile` scope.

```bash
curl -H "Authorization: Bearer YOUR_TOKEN" \
  https://api.appearance.app/v1/users/me/profile
```

The response body matches the JSON structure shown above. Individual zones can be accessed via query parameter:

```bash
# Hair zone only
GET /users/me/profile?zone=hair

# Structural measurements only
GET /users/me/profile?zone=structural
```
