## What is an Appearance Card?

An Appearance Card is a **structured representation** of either a user's appearance or an offering's requirements. Every entity in the Appearance system — every user scan, every hairstyle, every pair of glasses — gets a card.

Matching is **card-vs-card**: compare field A on the user card to field A on the offering card. Cards handle 90% of compatibility scoring. The remaining 10% comes from embedding-based aesthetic "vibe" matching.

```
User card: "I have texture family 3, short curly hair, oval face"
Offering card: "I suit textures [2,3,4], need at least short hair, suit oval/round faces"
→ Compatibility: 82/90
```

## Card Types

Every card has a `cardType` field:

| Type | Description | Example |
|------|-------------|---------|
| `user` | Generated from a user's appearance scan | "I have type 3B curly hair, medium density, oval face" |
| `offering` | Generated from a business's uploaded style photos | "This fade suits textures 1-3, medium/thick density, square/oval faces" |

## Schema

<Note>
  Cards are zone-aware. Hair fields are `null` when `zone !== 'hair'`, glasses fields are `null` when `zone !== 'glasses'`.
</Note>

### Universal Fields

| Field | Type | Description |
|-------|------|-------------|
| `cardType` | `'user' \| 'offering'` | Which side of the match |
| `zone` | `'hair' \| 'glasses' \| 'nails' \| 'tattoos'` | Which appearance zone |
| `audience` | `'masculine' \| 'feminine' \| 'androgynous' \| null` | Target audience |
| `computedAt` | `string` (ISO 8601) | When this card was generated |
| `cardVersion` | `1` | Schema version |

### Hair Fields

| Field | User Card | Offering Card |
|-------|-----------|---------------|
| `textureFamily` | User's texture (1-4 or `'bald'`) | Offering's primary texture |
| `textureType` | Andre Walker subtype (`'3C'`, `'2A'`) | Offering's subtype |
| `supportedTextures` | — | Which texture families work (`[2, 3, 4]`) |
| `lengths` | Current lengths `{ top, sides }` | Minimum lengths required |
| `density` | `'thin' \| 'medium' \| 'thick'` | — |
| `supportedDensities` | — | Which densities work (`['medium', 'thick']`) |
| `cutFamily` | Current cut family | Offering's cut family |
| `styleNature` | `'natural' \| 'protective' \| 'heat-styled'` | Same |
| `coverage` | `'full' \| 'thinning' \| 'sparse' \| 'patchy'` | — |
| `exposes` | — | `{ temples, hairline, crown }` booleans |
| `faceShape` | Detected face shape | — |
| `suitedFaceShapes` | — | Which face shapes this flatters |

### Hair Enums

```typescript
TextureFamily = 1 | 2 | 3 | 4 | 'bald'
// 1 = Straight, 2 = Wavy, 3 = Curly, 4 = Coily

LengthBucket = 'bald' | 'stubble' | 'short' | 'medium' | 'long'

FaceShape = 'oval' | 'round' | 'square' | 'diamond' | 'heart' | 'oblong'

CutFamily = 'fade' | 'taper' | 'buzz' | 'scissor' | 'longer_scissor' | 'other'
```

### Salon Fields (Feminine-Leaning Styles)

| Field | Type | Description |
|-------|------|-------------|
| `colorTechnique` | `string \| null` | e.g. `'balayage'`, `'highlights'`, `'ombre'` |
| `layeringMethod` | `string \| null` | e.g. `'long layers'`, `'blunt cut'`, `'graduated bob'` |
| `stylingMethod` | `string \| null` | e.g. `'blowout'`, `'air-dried'`, `'flat-ironed'` |
| `volumeLevel` | `string \| null` | `'flat' \| 'low' \| 'medium' \| 'high' \| 'voluminous'` |

### Style Properties (Offering Cards Only)

These describe what a style is like to live with — not compatibility, but lifestyle fit.

| Field | Type | Description |
|-------|------|-------------|
| `holdRequired` | `'low' \| 'medium' \| 'high' \| null` | How much product/hold needed daily |
| `shineLevel` | `'matte' \| 'satin' \| 'high-shine' \| null` | Visual finish |
| `dailyStylingTime` | `'quick' \| 'moderate' \| 'involved' \| null` | Morning routine effort |
| `supportedStrandThicknesses` | `('fine' \| 'medium' \| 'coarse')[] \| null` | Which strand diameters work |

### Glasses Fields

| Field | Type | Description |
|-------|------|-------------|
| `frameSizeCategory` | `'small' \| 'medium' \| 'large' \| 'extra-large' \| null` | Recommended frame size |
| `bridgeCategory` | `'narrow' \| 'medium' \| 'wide' \| null` | Bridge width category |
| `frameShape` | `string \| null` | Frame shape description |

## How Cards Are Built

**User cards** are built from appearance scan data — a multi-angle head capture analyzed by AI vision (Gemini). The scan extracts texture family, density, lengths, face shape, and coverage from photos + ARKit facial landmarks.

**Offering cards** are built from business-uploaded style photos. Gemini analyzes the reference photos and extracts structured attributes: what texture family the style was done on, what lengths it requires, what face shapes it flatters, and the new style properties (hold, shine, styling time).

Both card types are computed server-side and stored in Firestore. Cards are never computed on the client — the server is the single source of truth.
